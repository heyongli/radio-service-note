# tools/sch-true-finding/parameter_space.md — 参数调优空间学习记录

记录 **de-annotation / 走线 net / 彩线真理发现** 系列的参数调优规律与实测轨迹
(每次调参留档, 防"调好了但不知道为什么")。算法原理见 readme.md, 这里是参数空间。
**自监督指标见 readme.md §7** (判断好坏的标准), 本文件是调参记录。

## 调参规律

1. **先参数化再调优**: 阈值全走 CLI (architecture §5.9), 否则无法系统扫描。
2. **自监督指标先行**: 每次调参跑 readme §7 指标 (main_CC / cutting_segments /
   main_kept / 分通道精度) 判断好坏, 不依赖人工看图。
3. **对比基线不能用污染的主 net**: 主 net (gray<150 最大连通域) **45% 是彩色标注**
   (绿 19.2%), 不是纯走线 → 用 wire 连通域 (面积+长度签名) 作基线。
4. **分通道 > 统一 chandiff**: 每色显式 ops 的核心掩膜, 主 net 损失 35.5%→20.2%。
5. **COLOR_SPEC 需按图探测, 不能硬编码**: 印刷/渲染漂移; 探测逻辑待做 (todo)。
6. **调参策略**: 固定算法 → 单参数扫描 → 对照指标曲线 → 找平衡点。

## 参数空间 (de_annotate.py, 全 CLI)

| 参数 | 含义 | 调优方向 |
|---|---|---|
| `--diff-th` | BGR 通道差阈值 (统一 chandiff) | 过小吃走线, 过大漏标注; 分通道后基本不用 |
| `--dark-th` | 暗像素阈值 (走线/net 判定) | 150 剥离浅色标注; 过低丢深色标注 |
| `--gray-lo/--gray-hi` | 描边扩展灰度窗 (40-200) | 排除纯黑走线(灰<40)与亮背景 |
| `--s-min` | 饱和度下限 (通道差/HSV 模式) | 排除低饱和走线防误删 |
| **hue_mask s_min** (内置 30) | 色相扩展饱和度门槛 | **灰像素色相是噪声; 无它 red edge 568k 中 344k sat==0** |
| `--wire-radius` | 细走线判定 dt 上限 (3) | 排除符号体 (fat); 太小漏细走线 |
| `--min-bridge-wire` | 桥恢复所需邻接细走线成分数 (2) | 1 过松(恢复过多), 3 过紧(漏恢复) |
| `--edge` (默认含) | 色相描边扩展开关 | red 扩展过宽 (见轨迹); 桥恢复模式强制关 |

## 实测轨迹

### 2026-09-17 round A — 统一 chandiff 独立 (diff-th 40)
- 掩膜 459763 px; 主 net 损失 **35.5%** (321046 px), 主 net 碎 **258 块**
- 结论: chandiff 过宽, 吃走线; 用户报告"部分 net 联通区域丢失"正是此

### 2026-09-17 round B — 分通道核心掩膜 (每色 ops)
- 逐色主 net 损失: green **19.2%** (碎片来源) / red 0.3% / cyan 0.7% / yellow 0.0%
- union 246993 px, 主 net 损失 **20.2%**, 主 net 碎 **120 块**
- 结论: 分通道显著优于 chandiff; **绿色通道是唯一碎片来源** → 恢复逻辑主要作用于绿

### 2026-09-17 round C — + 桥恢复 (wire_radius=3, min_bridge_wire=2)
- 标注段 1542 段, **85 段恢复为桥** (54988 px), 其余置白
- **main_CC 120→1** ✓, **cutting_segments=0** ✓, main_kept 73.3%→**78.3%**
- 结论: 桥恢复 (标注段邻接 ≥2 细走线成分) 修复连通性; 判定只在标注像素邻域算 (~14s)

### 2026-09-17 round D — 独立模式描边扩展的 red 假阳性
- 独立模式默认含描边扩展 → 掩膜 800615 px, 主 net 碎 **465 块**, main_kept **47.2%**
- 定位: red hue 扩展 568682 px, 其中 **344277 px sat==0** (纯灰像素色相噪声)
- 修正: hue_mask 加 **s_min=30** → red edge 568k→216k (绿/青 99% 保留)
- 修正后: 独立模式掩膜 800615→**444445** px, main_kept 47.2%→**64.8%**, main_CC 465→**179**
- 教训: **色相掩膜必须查饱和度**; 灰像素色相无意义
- 仍比核心掩膜(311k/120块)差 → 独立模式的描边扩展对连通性仍有害, 桥恢复模式
  强制关 edge (核心掩膜) 是正确选择

### 2026-09-17 round E — 亮度/色纯度判别 (用户假设)
- 绿标注与走线融合区 (灰40-120, 高饱和). 亮度 2D 分布: 走线核 灰40-80/高饱和,
  标注 灰100-120/高饱和. L=120 亮度保走线: main_kept 98.8% main_CC=5, 但
  染回走线色 → 粗线 184k (不可用). 简单联合 (亮度+纯度) 连通性反而更差.
- 结论: 单像素判别分不开"融合走线"与"标注本身"; 需结构/连接信息 → 线续接.

### 2026-09-17 round F — 线续接数学法 (wire_recover, 已废弃)
- 数学法: 可见走线骨架端点共线反向配对, 画直线恢复覆盖走线 (inpainting).
  实测 bridged_pairs=626, main_CC 258→186, 无粗线.
- **用户判定: 接线完全不能用** (画错线/乱接). 已删除 wire_recover.py.
- 教训: 共线端点配对缺乏"该处确应有走线"的强约束, 把不相关的断口接在一起.

### 2026-09-17 最终结论 (用户裁定)
- **deannot_chandiff_final.png (独立 chandiff 模式, --diff-th 40 --color all) 是最终答案**:
  彩色残留=0, 线宽 p90=2.0, main_CC=258, main_kept 64.5%.
- 桥恢复 / 亮度保走线 / 线续接 三类"恢复走线"尝试全部失败 (粗线伪影 / 乱接线),
  均不可用. 去标注就干净置白, 不要试图恢复被覆盖的走线 (与 readme §6 一致).
- "部分 net 联通区域丢失" 在 chandiff final 中是**可接受代价** (标注本来就该断连).

### 2026-09-17 分通道特性 (用户观察 + 实测)
- **chandiff 对绿色标注可能丢线, 但对橙色(TX)/青色(common)完全无损**.
  逐色主 net 损失实测: green **19.2%** (唯一碎片来源) / red 0.3% / cyan 0.7% / yellow 0.0%.
- 原因: 绿与走线色调融合 (绿线灰度~106, 与走线灰度段重叠), 去除时吃走线;
  橙/青/黄与灰走线通道差分离干净, 置白不碰走线.
- 含义: chandiff final 的断线**全部来自绿色标注**; 若未来要改善连通性,
  只需针对绿色通道 (RX 线) 做局部处理, 橙/青/黄保持纯 chandiff (无损).
- 各色实现 (de_annotate.py COLOR_SPEC ops): green g>120/r<110/b<110;
  red r>150/g<110/b<200+色相; cyan g>120/r<110/b>120; yellow g>120/r>120/b<100.
### 2026-09-17 round G — 段内暗芯 (lum_frac25) = 最终解法 (用户裁定)
- **方法**: 每彩色段保留亮度最低 25% (相对暗芯=走线) 染回走线色, 其余置白.
- **用户评价**: 不断线、不变细 (走线连续且全宽), 轻微彩色残留可接受.
- **实测**: 彩色残留=0, 线宽 p90=2.0 (不变细), 宽线 27365 (同 chandiff), main_kept 70.5%.
- **对比 chandiff**: chandiff 主net 258 块 (断线), lum_frac25 不断线.
- **为何有效**: 每段内"相对最暗的芯"= 走线在标注下的位置 (色调融合但亮度相对低);
  按段内相对暗度, 不用全局亮度 (全局会把整条绿带当走线).
- **指标教训**: main_CC 对 lum_frac25 显示 1153 (碎), 但用户视觉判定"不断线" ——
  main_CC 数的是原主net区域内的连通域数, 保留芯是小片但沿走线排列视觉连续;
  自监督指标也要对照视觉 (用户是最终裁判).
- **输出**: projects/icom2200h/annot/deannot_lum_frac25_final.png (固化).
- frac 扫描 (保留芯数/main_kept/main_CC): 0.15→37k/68.1%/616, 0.25→62k/70.5%/1153,
  0.40→112k/75.0%/1883. 25% 是"足够保留+不过度"的平衡.

### 2026-09-17 round H — lumfrac 擦除参数 (用户要求记录; 沿绿线有边缘剩余)
- **问题**: lumfrac 擦除后沿标注线 (尤其绿) 有边缘剩余/没擦干净的地方.
  定位: 残留是 chandiff 10-40 的浅色像素 (标注带抗锯齿边缘), chandiff>40 掩膜
  没抓住; 且 keep_color 前芯被染成灰 (用户要求保持彩色).
- **参数 (de_annotate_lumfrac.py)**:
  | 参数 | 默认 | 作用 | 实测 |
  |---|---|---|---|
  | `--frac` | 0.25 | 每段保留亮度最低比例 (暗芯=走线) | 0.15-0.40 扫描见 round G |
  | `--light-th` | 0(关) | 浅色残留清除: chandiff>此值也置白 (清带边缘) | 15/12/10/8 → light_resid 75k/71k/52k/52k |
  | `--keep-color` | 关 | 保留芯用原彩色 (绿线保持绿), 不染走线灰 | 用户要求保持彩色 |
- **keep_color 后 colored_resid 计数含保留芯** (52000-55000 是保留的绿芯, 非残留);
  需另看 light_resid(10-40) 判断擦除干净度. light-th 8-10 擦得更净.
- **待调平衡**: light-th 过低会吃走线边缘 (把灰走线的浅色抗锯齿也置白), 
  需对照视觉定平衡点 (当前测试 lt 8-15).

### 2026-09-18 round I — wirelum 亮度法只对绿色有效 (用户观察)
- **亮度保走线 (wirelum) 只适用于绿色 (RX)**: 绿标注与走线色调融合 → 走线被
  染暗, 亮度更暗=走线 (L=120 全保留). TX(土黄, 灰155)/common(青, 灰129) 标注
  亮度高, 走线在其下不被染暗 → 亮度法区分不了 (M120 全删, 自适应也只保留
  每色亮度中位以下的半段).
- 结论: **RX 走线恢复用亮度法; TX/common 标注本身不融合走线, 直接颜色去除
  即可 (chandiff/chmask)**, 无需亮度法.
- 工具: `wire_lum_detect.py` (默认 M120 保色 + green,tuHuang,cyan; 三色完整
  需 --wire-lum 0 自适应, 但 TX/common 效果有限).
