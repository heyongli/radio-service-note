# tools/schematic_flow_walk — 原理图信号流走线

## 文件清单
| 文件 | 用途 |
|---|---|
| `schematic_flow_walk.py` | 主程序: 彩线掩膜 + flood 走线 + 断口采样 + OCR → chain_order |
| `readme.md` | 本文档 (修改前必读, 算法说明固化用户经验) |

## 目的
从原理图渲染图识别信号流彩线, 像流水一样沿彩线 flooding 走线,
排出**流经元器件链序**, 生成 `chain_order_rx.json` / `chain_order_tx.json`。

## 彩线颜色约定 (实测)
| 颜色 | 含义 | 掩膜条件 |
|---|---|---|
| 绿 | RX 信号流 | `g>120, r<110, b<110` |
| 红 | TX 信号流 | `r>120, g<110, b<110` |
| 黄 | 控制信号 | `r>120, g>120, b<110` |
| 青 | common line (公共) | `g>120, b>120, r<110` |

方法依据: best_practices §5b-2 (绿线掩膜 + 膨胀 + 位号邻近判定)。

## 算法说明 (固化用户经验, 修改前必读)

### 1. 分辨率与线宽
- **用 600dpi** 原理图 (300dpi 绿线只捕获薄线段带, 细节丢失)
- **探测绿线宽度** `line_width()`: 按列扫描绿像素竖直连续段, 取中位段长
- **采样半径 = 3x~5x 线宽**: 关联/搜索窗口按线宽自适应, 而非固定像素

### 2. 符号形状 (原理图元件按符号定位, 参考 PCB 处理方式)
| 符号 | 形状 | 检测方法 |
|---|---|---|
| 三极管 Q | 圆 | 轮廓圆度 circ>0.82, 面积按 dpi² 缩放 |
| 电容 C | `-| |-` 两条平行短线 | Hough 线配对: **两板之间必须为空 + 两侧必有接线** |
| 电阻 R | 折线锯齿 / 长方块+两侧接线 | 斜线簇成串 / 小矩形+两侧线 |
| 电感 L | 一串小弧 (arc chain) | Hough 圆同行/列成串 ≥3 |
| IC | 矩形本体 | 大矩形 + 4 角 + 填充率 |

**为何用符号而非文字**: refdes 文字印在符号上方, 不在彩线上; 符号本体才连到彩线。

### 3. 绿线断口 = 元器件 (核心洞察)
- **绿线连续经过导线, 经过元器件 (电容/三极管/IC) 时断开** → 断口位置就是元器件
- 断口 gap = 元器件尺度: 15-18px=小电容/电阻, 25-80px=三极管/中器件,
  127-228px=IC (大封装)
- 按断口尺度 **6x6~8x8 平铺裁切**, 该截图内识别元器件类型 + OCR refdes
  (自适应采样: 大断口大截图读到 IC4 TA31136FN, 小断口小截图读单个 C124)

### 4. 排除非元器件断口
- **几像素小断层 / 可 flood 过去 = 联通**: 先强闭合 (close_k≥线宽) 弥合 → 视为同一段
- **空心箭头不是元器件**: 箭头用细黑线截断绿线, 是**封闭边框** (空心三角轮廓) →
  断口处检测到封闭空心轮廓即箭头, 剔除
- **细黑走线横穿绿线 (不是器件)**: schematic 黑走线有时横穿绿线导致误判。
  特征: 横穿黑线宽度 < 绿线宽的 **1/5**, 且沿法向对小范围截图会到图边沿。
  → 宽度 < 绿线 1/5 的暗特征忽略 (flood 冲过去), 只有 ≥ 绿线宽一部分才算器件

### 5. 像流水一样 flooding (跟随拐弯 + 多流出口)
- **逐行/逐列扫描会漏拐弯** → 必须像流水 flooding 沿绿线走
- **断口处向所有方向探索**: 会找到它的流出口
- **一个元器件可有多个流出口** (如 IC 多引脚) → 用**连通域图 BFS**:
  每个域向前沿全方向探测相邻域, 从 seed 域 BFS 遍历, 天然处理分支
- **绿线一般沿着一条黑线走** (重要特征): 彩线叠加在黑色走线上;
  断口 = 绿线在器件处离开黑线. 探测时绿线与黑线的相对关系是判据
- **绿断时沿未断黑线前进**: 器件处绿线断但黑走线未断 (连续) →
  沿黑线前进方向穿过器件到下一段绿线 (绿+黑双线追踪)
- **小黑圆点 = 两条线交叉点**: 此时沿**有绿线覆盖的黑线**走 (选绿覆盖的支路)

### 6. OCR 关联最相关元器件
- OCR 网格 tile 读 refdes (600dpi)
- 每个断口附近 OCR → 关联**最相关元器件** (类型前缀匹配 Q→圆/C→电容/IC→矩形/L→电感)

### 7. 链序
- 按 flood 走线顺序 (断口顺序) 排列 → 流经元器件链序
- 主路甄别: 触及 ≠ 主路 (§5b-2), 需按电路原理

## 算法步骤
1. 颜色掩膜 → 彩线图; 探测线宽
2. 强闭合弥合小断层 (视为联通)
3. 连通域图: 每个域全方向探测相邻域 (gap≤max_gap) → 断口
4. 从 seed (ANT) BFS 遍历连通域图 → 流经断口序列
5. 每个断口: 排除空心箭头 → 按 gap 自适应 6-8x 裁切 → 识别符号 + OCR refdes
6. 输出 chain_order (断口顺序 = 流经元器件链序)

## 探索经验总结 (2026-09-16, round 010, 30/31 召回)

### 有效方法 (已固化)
1. **三极管用 HoughCircles 检测**: 轮廓圆度法被走线破坏 (圆与连线合并 → 圆度<0.8),
   HoughCircles (r 10-35 @600dpi) + 绿线邻近过滤 效果好
2. **关联距离要够大 (220px)**: 原理图标号文字离符号可达 200px+, 默认 120 漏检
3. **反向 OCR 验证 symbol center**: 关联后反向 OCR 符号中心确认, 旋转 0/90/180/270
   + 1↔I 修正 (FI3↔F13) + FL-363 陶瓷滤波例外; 失败则在文字附近找正确符号
4. **同 refdes 去重**: 一个标号映射多个符号时保留验证 OK 的
5. **绿线流过判定**: 符号两侧沿流向共线有绿 (E+W 或 N+S); band=22, side=20,50 最优

### 里程碑
- round006: 24/31, symbol center 58%
- round008: 23/31, symbol center 92% (去重+旋转 OCR)
- round010: **30/31**, symbol center 92% (HoughCircles + assoc 220)
- round013: **30/31 + symbol 边界 100%** (337/337)
- 仅剩 C216: 原理图 OCR 未读到标号 (在 C224 正下方, 接 IC4 pin5)

### 关键突破 (round013)
1. **refdes 前缀定符号类型**: Q/TR→圆, IC/FI/X→方块, C→电容, R/L→线.
   (Hough 圆噪声导致 R 误判 circle, 改用前缀可靠)
2. **HoughCircles 检测三极管圆**: 薄圆+走线轮廓圆度被破坏, Hough 可靠
3. **IC 空心方块轮廓**: 放宽填充率 (IC 是黑边空心框)
4. **label 文字框定位**: OCR 预计算 text_box, symbol 不得落在框内 (on_label 检查)
5. **label 附近纠正符号位置**: 反向 OCR + 黑边边界反向锚定真实符号
6. **符号边界验证 (sch_symbol_selfcheck 独立程序)**: 消费前管线结果做筛选,
   圆/方块须包含红点, 电容须线对, 电阻/电感须连续线

### 综合探测管线 (detect_flow_components)
1. **OCR 全量 refdes** (网格 tile, 600dpi) → 位置集
2. **符号检测触点绿线**: 电容(-| |-) / 三极管(圆) / IC(矩形) — 只留触点绿线的
3. **关联**: 每个 refdes → 最近符号 (距离 ≤150, 类型匹配加分)
   - 全局符号集关联比逐 refdes 局部检测**更有效**
   - 全局失败时**本地回退** (detect_symbol_near + 绿触点)
4. 符号触点绿线 = 在 flow 上 → 流经元器件

### 校准结果 (IC-2200H RX, 31 组件 ground truth)
- 迭代后 **28/31 召回** (90%), 再经"绿线流过"过滤后显示 21/31
- 关键改进: 关联距离 80→150, 加 IC 检测, 类型加分, 本地回退
- 电容检测窗口采样 (69→98 电容, 恢复 C77/C80)

### 关键识别要点
- **符号位置 ≠ 标号位置**: 标号在符号上方, 必须关联"标号→最近符号"(数据库)
- **主路直通 vs 支路**: 主路符号绿线两侧共线通过 (入+出); 支路只有单侧 (死端)
  → `green_sides` 证据; 非流过不显示
- **"绿线流过"判据**: 符号两侧沿流向共线有绿 (E+W 或 N+S)
- **关联数据库**: `nettable/sch_label_symbol_assoc.json`
  (标号→符号关联 + 符号类型 + 绿线侧边证据)

### 识别 / 连线 / 渲染 分层
识别器件(本工具) → 连线路由(signal_flow_route) → 渲染(svg_render) 应分开;
本工具只负责**识别 + 关联数据库**。

## 用法
```bash
# 600dpi 原理图, RX 绿线
python3 tools/schematic_flow_walk/schematic_flow_walk.py \
  --img projects/icom2200h/render/rxtx-sch-600-1.png \
  --color green --seed 626,1480 \
  --out chain_order_rx.json --symbols

# TX 红线同理 --color red
```

## 输入 refdes JSON (可选, OCR 关联用)
```json
[{"refdes": "Q27", "x": 1532, "y": 858, "role": "RF-AMP"}]
```
x/y 为原理图 600dpi 空间 OCR 文字位置。

## 输出 chain_order JSON
```json
{"chain": [{"idx": 1, "refdes": "J11", "sch_px": [315,741], "type": "connector",
            "walk_d": 0, "status": "confirmed"}, ...]}
```
